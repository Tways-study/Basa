## 2026-10-30 (Phase 5, review UI v1, branch `alex/review-ui`)

The reviews live on their own route, so the frozen `ScanResult` shape is unchanged.

## 2026-10-31 (Phase 6, offline outbox; capture screen redesign; PRODUCT.md)

- **Outbox built (Phase 6 tasks 1 to 3), Alex with Claude.** Capture now saves the downscaled photo to IndexedDB first (`lib/outbox/client.ts`, `idb`), then sends through the shared sender `lib/outbox/send.ts` (the capture screen's old fetch and `SyncAcceptedSchema` check, moved, not rewritten). `lib/outbox/runner.ts` sends oldest first and saves each outcome before the next, so closing the tab loses nothing; an item left in `syncing` by a closed tab is recovered at the start of the next run. Triggers: app start, the `online` event, a "Sync now" button, and a timer for the next backoff time (2 s, 4 s, 8 s, capped at 60 s; 8 attempts, then "Not sent" with Try again or Discard). A refusal (400, 413, 415) is not retried; 5xx, 408, 429, no network and a malformed reply are. The blob is dropped once the server accepts the photo. Rows show Saved on device, Sending, then the server's own status (Waiting, Reading, ...) polled with backoff, and link to the scan. If IndexedDB is unavailable the screen says so and sends straight away with the same sender.
- Idempotency: the scan id is made once at capture and stored with the item; a repeat `POST /api/sync` of a known id is a no-op on the server. One run at a time per tab (shared in-flight promise); two tabs could both send, and the server still creates one scan.
